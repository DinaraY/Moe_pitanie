# Моё питание: сайт и отдельный backend

Проверено 08.11.2026: опубликованный Worker отвечает Hello World!, GitHub Pages работает. Этот PR не публикует и не объединяет изменения автоматически. Главная сохраняет примерное меню и локальное сохранение; новая connect.html содержит подбор из реального каталога после настройки сервера.

## Реализовано

- Отдельный Cloudflare Worker, без assets и маршрутов сайта.
- OAuth 2.0 + PKCE S256, шифрованные сессии и выход: [OAUTH.md](OAUTH.md).
- Нормализация товаров по полям официального CLI: ID, цена, единица продажи, масса упаковки, КБЖУ с явно указанной базой 100 г, состав, категория, наличие и дата проверки. Отсутствующее значение остаётся неизвестным. Мл не превращаются в граммы; Для нескольких производителей сохраняются все варианты: одинаковые значения считаются точными, разные показываются диапазоном без усреднения. Если хотя бы один вариант неполный, диапазон не рассчитывается.
- Подбор девяти групп: яйца, авокадо, помидоры, готовые блюда, йогурт, творог, яблоки, пастила, шоколад. Два дня × завтрак/обед/ужин/перекусы. Для готовых блюд проверяется категория. Это предложения товаров/порций, не гарантия попадания в медицинскую цель по калориям. Фильтры названий эвристические: выбранные продукты пользователь проверяет.
- Замена из полученного каталога и редактирование массы порций. КБЖУ считаются по съедаемой массе, стоимость — по упаковкам с расчётными остатками. Для кг количество округляется вверх до 0,01 кг, сумма помечается предварительной. Доставка в сумму не входит.
- Серверный черновик корзины на 5 минут, привязанный к сессии, шифрованный AES-GCM. Пользователь видит повторно проверенные данные и явно подтверждает конкретную версию. Изменение цены, массы упаковки, количества или недостаток наличия требуют нового черновика. Неверная/истёкшая сессия не переводится молча в публичный каталог.
- Создаётся только ссылка vkusvill_cart_link_create. Операций оплаты/оформления заказа в коде нет. Повторное подтверждение готового черновика возвращает ту же ссылку; конкурентный/неуспешный вызов не запускает повторное создание. Выход из приложения лишает сессию доступа к черновикам; записи также удаляются по TTL.

## Источники и живая проверка

- [Официальный MCP](https://mcp.vkusvill.ru/mcp).
- [Официальный manifest](https://github.com/vkustech/vkusvill-mcp-server-manifest).
- [Официальный CLI, зафиксированная версия](https://github.com/vkustech/vkusvill-cli/tree/e49df83b43429c32cb5c9c6bbd6154757f72bb1a): src/api.js — q/id и обёртка data/items, src/product.js — price.current, weight.value/unit, properties, available_quantity; src/auth.js — catalog.search и client_secret_post. Поля проверены по исходнику; реальных товаров из тестовых fixtures приложение не показывает.
- [Живые OAuth metadata](https://oauth.vkusvill.ru/.well-known/oauth-authorization-server): подтверждены issuer https://oauth.vkusvill.ru/, endpoints /oauth2/auth и /oauth2/token, PKCE S256, методы client_secret_post и client_secret_basic. Метаданные также объявляют device code, client credentials, implicit и refresh grants; это не означает, что каждый grant разрешён конкретному клиенту. Для пользователя приложение использует только authorization code + PKCE. Refresh не реализован.
- [Статья команды ВкусВилла](https://habr.com/ru/companies/vkusvill/articles/1094732/): персональная регистрация клиента, адрес доставки в личном кабинете.
- [Cloudflare Request](https://developers.cloudflare.com/workers/runtime-apis/request/): исходящие запросы используют redirect:manual с отказом на 3xx; redirect:error не поддерживается Workers.
- [Спецификация авторизации MCP](https://modelcontextprotocol.io/specification/2025-06-18/basic/authorization).

Прямой MCP initialize и protected-resource metadata из среды разработки по-прежнему получают HTML Access Blocked. Проверка OAuth metadata по правильному issuer успешна. После публикации через GitHub проверены живые tools/list (HTTP 200), поиск йогурта (10 реальных товаров с ценами/массой/КБЖУ), карточки и двухдневный план (все 9 групп заполнены, ошибок нет). Наличие по адресу, OAuth вход и cart-link пока не проверены. Для нового тестового moe-pitanie-2 публичный CATALOG_ENABLED=true, чтобы проверить доступ из Cloudflare. OAUTH_ENABLED и CART_ENABLED=false. В отдельных staging/production-конфигурациях все флаги false. При изменившейся схеме операция отклоняется, данные не выдумываются.

## API

Все ответы JSON, no-store. Origin разрешён только https://dinaray.github.io (без пути). CORS не является авторизацией. Персональная сессия передаётся как Bearer идентификатор приложения, никогда как клиентский токен магазина. Rate limiter обязателен.

| Маршрут | Назначение |
| --- | --- |
| GET /api/status | Готовность сервера и флаги |
| GET /oauth/start, /oauth/callback | Вход через официальный OAuth |
| GET /api/session, DELETE /api/session | Проверка и завершение сессии |
| GET /api/tools | Схемы только разрешённых операций чтения |
| POST /api/catalog | Низкоуровневый вызов поиска/карточки/аналогов |
| POST /api/search | `{ "query": "творог" }` → нормализованные товары |
| POST /api/product | `{ "id": <реальный ID из поиска> }` → свежая карточка |
| POST /api/plan | `{}` → меню на два дня и пулы замен, до девяти последовательных поисков |
| POST /api/cart/draft | `{ "entries": [{ "id": <реальный ID>, "grams": <съедаемая масса> }] }`, нужен вход |
| POST /api/cart/confirm | `{ "id": <id черновика>, "version": <его версия>, "confirmed": true }`, нужен вход и CART_ENABLED=true |

В открытом /api/catalog нельзя вызвать корзину, персональные скидки, историю или другие инструменты. Схемы tools/list перечитываются перед работой. Для cart-link требуется текущая схема products[].id:int, q:number; неожиданное изменение блокирует операцию.

## Развёртывание

С телефона через GitHub-интеграцию Cloudflare: [DEPLOY.md](DEPLOY.md). Доступ к Cloudflare из среды разработки не предоставлен.

С компьютера из worker/:

```sh
npm test
npx wrangler@4 login
npx wrangler@4 whoami
npx wrangler@4 deploy --config wrangler.staging.jsonc --dry-run
npx wrangler@4 deploy --config wrangler.staging.jsonc
```

Это создаёт **moe-pitanie-api-staging**. Для существующего production использовать отдельную конфигурацию:

```sh
npx wrangler@4 deploy --config wrangler.production.jsonc --dry-run
npx wrangler@4 deploy --config wrangler.production.jsonc
```

Сначала сохранить текущую версию production в Dashboard → Deployments для отката. Не удалять текущий Worker. Для отката выбрать прежнюю версию. Конфигурации не содержат assets/routes сайта. GitHub Pages не переносится в Cloudflare.

После deploy проверить /api/status, затем включать по этапам:

1. CATALOG_ENABLED=true: tools/list, поиск, карточка, КБЖУ и меню. Сверить минимум одну реальную карточку с сайтом: цена, единица, масса, база КБЖУ. Публичный каталог не подтверждает доставку.
2. OAuth Secrets и OAUTH_ENABLED=true по OAUTH.md: вход на телефоне, отказ, истечение/выход, изоляция сессий. Наличие известно только при авторизованном запросе и явном числовом available_quantity; отсутствие данных остаётся unverified.
3. Проверить черновик по адресу в Долгопрудном. Оставить CART_ENABLED=false до сверки текущей схемы и свежего расчёта.
4. Включить CART_ENABLED=true и проверить явное подтверждение, изменение цены, истечение и повторный клик. Никакой заказ автоматически не оформляется. Итоговую цену и доставку пользователь подтверждает во ВкусВилле.

Профиль 72 → 65 кг, 43 года, 167 см, сидячая работа отображается как контекст. Старый калькулятор — предварительный ориентир, а не медицинское назначение. До персонального ограничения рациона нужно уточнить применимость формулы, аллергии и ограничения питания.
