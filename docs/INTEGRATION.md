# Отдельный Worker и интеграция ВкусВилл

Проверка 08.11.2026: в main был только index.html. Worker по указанному адресу отвечал Hello World!. Сайт остаётся на GitHub Pages. Этот PR не развёртывает Worker и не включает живой подбор меню.

## Что подготовлено

worker/ — независимый Worker без статических assets, сборки сайта, маршрутов домена GitHub и автоматического деплоя. По умолчанию создаётся отдельный moe-pitanie-api-staging, каталог выключен. GET /api/status сообщает ограничения. GET /api/tools получает текущие схемы трёх разрешённых операций чтения. POST /api/catalog принимает {"tool":"имя из tools","arguments":{}}: аргументы заполнять по inputSchema из tools/list, а не по догадке. В ответе исходные данные MCP, источник и время проверки. В этом этапе нет нормализации цен и КБЖУ, авторизации, автоматического меню или корзины.

Разрешены только поиск, карточка и аналоги. История заказов, персональные скидки (их вызов может менять подбор скидок), корзина и любые новые инструменты запрещены. Браузерные Authorization и Cookie не пересылаются. CORS допускает https://dinaray.github.io (origin без пути), но не является авторизацией. API содержит только публичные данные и ограничивает запросы по IP. Без binding лимитера работает отказ. Ответы и ошибки не кешируются, upstream ошибки не раскрываются. Секреты и пользовательские токены здесь вообще не используются.

## Проверенные источники и ограничения

- [Официальная страница MCP](https://mcp.vkusvill.ru/mcp): публичные инструменты доступны без входа; полный доступ — OAuth 2.0 + PKCE, регистрация клиента, адрес доставки в личном кабинете.
- [Официальный manifest](https://github.com/vkustech/vkusvill-mcp-server-manifest): OAuth и позднее refresh token; корзина — ссылка, до 100 товаров.
- [Статья команды ВкусВилла](https://habr.com/ru/companies/vkusvill/articles/1094732/): персональный OAuth-клиент привязан к карте создателя; публичный каталог не подтверждает ассортимент по адресу. Статья старше обновления manifest о refresh token: реальные сроки токенов и scopes нужно читать из текущих metadata/ответов, не фиксировать по статье.
- [Спецификация авторизации MCP](https://modelcontextprotocol.io/specification/2025-06-18/basic/authorization).
- [Конфигурация Wrangler](https://developers.cloudflare.com/workers/wrangler/configuration/).

Прямые запросы к MCP и protected-resource metadata из среды разработки получили HTML Access Blocked. Это не доказательство недоступности из Workers. Живые tools/list, схемы результатов и OAuth endpoints здесь не проверены. Не следует обходить блокировку или придумывать endpoint/token scopes. При HTML, 401/403, таймауте или изменении протокола API возвращает ошибку без фиктивных данных.

## Развёртывание вручную в Cloudflare

1. Сохранить текущую версию и настройки moe-pitanie-api в Cloudflare Dashboard → Workers & Pages → moe-pitanie-api → Deployments / Settings; записать версию для rollback. Не удалять текущий Worker.
2. Установить актуальный Wrangler 4 по официальной инструкции Cloudflare. Из корня репозитория:

   ```sh
   cd worker
   npm test
   npx wrangler@4 login
   npx wrangler@4 whoami
   npx wrangler@4 deploy --dry-run
   npx wrangler@4 deploy
   ```

   Убедиться, что выбран нужный аккаунт. Эти команды создают staging, не меняют production. Если организация закрепляет версии CLI, использовать её одобренную версию Wrangler 4.
3. Открыть выданный Cloudflare URL /api/status: catalogEnabled=false, cartEnabled=false. Проверить, что существующий GitHub Pages открывается как раньше.
4. Только для проверки публичного каталога поменять CATALOG_ENABLED на "true" в worker/wrangler.jsonc и повторить deploy staging. Проверить /api/tools. Binding CATALOG_LIMITER обязателен. При MCP_UNAVAILABLE смотреть статус upstream без записи токенов и персональных данных; обратиться к поддержке ВкусВилла, если доступ блокируется из Cloudflare.
5. Для smoke test взять inputSchema vkusvill_products_search из /api/tools, заполнить реальными аргументами и отправить POST /api/catalog. Сверить цену, единицу продажи, вес и КБЖУ с карточкой; данные теста не публиковать как наличие для Долгопрудного. HTML и upstream ошибки должны давать 502; неизвестный tool — 400; /api/cart — 501.
6. После проверки staging можно явно заменить name на moe-pitanie-api и выполнить dry-run/deploy в том же аккаунте. Это заменит Hello World!; не добавлять assets, routes или GitHub Pages deployment. Для отката использовать сохранённую версию в Dashboard. Автоматический deploy из PR не настроен.

## OAuth: следующий обязательный этап

1. В личном кабинете ВкусВилл выбрать точный адрес в Долгопрудном. Одного названия города недостаточно для подтверждения наличия.
2. Зарегистрировать персональный OAuth-клиент на https://vkusvill.ru/oauth/registration/. Планируемый callback для отдельного backend: https://moe-pitanie-api.statusdi.workers.dev/oauth/callback. **В текущем коде этот callback возвращает 501: не запускать авторизацию до реализации и проверки следующего этапа.** Для многопользовательского приложения отдельно подтвердить доступность такого клиента у ВкусВилла.
3. Client ID и client secret из письма сохранять только в серверной конфигурации. Для будущей реализации можно использовать `npx wrangler@4 secret put VV_CLIENT_ID` и `npx wrangler@4 secret put VV_CLIENT_SECRET`. Не вводить значения в чат, HTML, localStorage, URL, git или GitHub Actions logs. В этом PR эти bindings не читаются.
4. Получить текущие resource metadata / authorization-server metadata согласно спецификации. Проверить issuer и HTTPS endpoints по официальному источнику, запретить произвольные адреса и redirects. Зафиксировать реальные scopes и поддерживаемый client authentication method. Сейчас эти значения не установлены.
5. Реализовать code flow с PKCE S256, случайным одноразовым state, проверкой callback URI, коротким TTL и атомарным погашением state в Durable Object. Верификатор и токены хранить только на сервере, изолированно по пользователю, в шифрованном хранилище; ключ — Worker Secret. Не хранить сессии в глобальной переменной Worker. Refresh выполнять только если объявлен и разрешён; поддержать logout/отзыв/истечение без fallback в чужую сессию.
6. Для Pages и workers.dev не полагаться на сторонние cookies. До интеграции выбрать и проверить схему собственной аутентификации приложения (например, общий собственный домен или короткая сессия приложения в памяти с повторным входом). OAuth-токены ВкусВилла не должны попадать во frontend. Защитить изменяющие операции от CSRF и повтора; CORS не заменяет проверку пользователя.

## Приёмка реального меню и корзины

Сохранить профиль: 72 → 65 кг, 43 года, 167 см, сидячая работа, без лимита бюджета. Текущий калькулятор — предварительный ориентир с прежними коэффициентами, не назначение. Перед персонализацией уточнить пол/применимость формулы, ограничения питания и аллергии. Два дня × завтрак, обед, ужин и перекусы. Завтраки — яйца, авокадо, овощи с простой готовкой; обеды и ужины — готовые блюда; перекусы — йогурт, творог, фрукты, пастила, сладкое.

Каждая позиция должна иметь настоящий product ID, источник, дату проверки, цену и единицу продажи, массу упаковки, порцию, КБЖУ с указанием базы (100 г / порция). Не считать неизвестные значения нулём. КБЖУ меню считать по съедаемой массе; стоимость корзины — по числу покупаемых упаковок, с остатками. Для весовых товаров показывать предварительную сумму. Замены получать из реального каталога/аналогов и повторно проверять наличие с OAuth. Недоступные товары не включать как доступные.

Корзина: сервер создаёт неизменяемый черновик с ID/количествами, ценами, сроком действия и принадлежностью пользователю. UI показывает состав и общую сумму. Только отдельное явное подтверждение именно этой версии разрешает одноразовое создание ссылки vkusvill_cart_link_create. Изменение состава/цен или истечение срока требует нового подтверждения; повторный клик не повторяет действие. Ссылка разрешается только на проверенные официальные HTTPS домены ВкусВилла. Оплата и оформление заказа остаются на сайте/в приложении ВкусВилла, без автоматического вызова заказа. В текущем этапе любые /api/cart* заблокированы, даже при передаче confirmed=true.

До прохождения этих критериев существующее меню на сайте остаётся честно помеченным примером, а не подбором товаров ВкусВилла.
