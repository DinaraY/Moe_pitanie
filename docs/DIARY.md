# Дневник питания и предпочтения

На странице `connect.html` дневник хранит только явно добавленное пользователем съеденное. Предложенное меню и покупки не добавляются в него автоматически. У каждой записи есть локальная календарная дата, съеденная масса и снимок КБЖУ товара на момент записи. Изменение каталога не переписывает прошлые записи. Неизвестные КБЖУ блокируют расчёт полного остатка, диапазоны разных производителей сохраняются диапазонами.

История ограничена последними 90 днями и 500 записями, оценки — 500 товарами. Записи можно удалить отдельно; историю и оценки можно очистить вместе. Хранение: localStorage, ключ `moe-pitanie.journal.v1`. История остаётся после выхода из магазина, принадлежит браузеру, не синхронизируется и может исчезнуть после очистки данных сайта или в приватном режиме. На общем устройстве её видят другие пользователи этого браузера. Ключи магазина и сессии в дневнике отсутствуют.

`POST /api/plan` принимает необязательные `preferences: { blocked: number[], liked: number[], recent: number[] }`. Передаются только идентификаторы товаров, без полных записей дневника. Товары из blocked исключаются; recent содержит уникальные товары, съеденные за последние семь дней. Повторы получают небольшой штраф при подборе, понравившиеся — небольшой приоритет. Главным критерием остаётся соответствие дневному КБЖУ; при ограниченном ассортименте повторы возможны. Оценка применяется к следующему подбору. Текущий план сохраняется с предупреждением, корзина требует нового расчёта и подтверждения.

Два дня планируются как полные будущие дни. Остаток сегодняшнего КБЖУ показывается в дневнике отдельно и не вычитается из обоих будущих дней. Автоматического подбора оставшихся приёмов пищи сегодня пока нет.

## Граница подключения ИИ

Это алгоритмический подбор, не вызов ChatGPT/OpenAI API. Серверный вызов модели, облачная память и свободный диалог пока не реализованы. Для следующего этапа потребуется отдельно настроенный серверный API-ключ, выбор модели и явное описание пользователю передаваемых данных. Секрет нельзя помещать в GitHub Pages, репозиторий или localStorage.

Модель должна выбирать только идентификаторы из реально полученного каталога; расчёт порций, проверка КБЖУ, цен и остатков выполняются кодом. Создание корзины остаётся отдельным действием после подтверждения. История дневника не должна передаваться магазину в поисковых запросах или автоматически добавляться в заказы.

## Проверка

`npm test`: даты, неизвестные КБЖУ, диапазоны, остаток/превышение, снимки нутриентов, повреждённое хранилище, исключения и валидация идентификаторов; также прежние тесты OAuth и подтверждения корзины. Браузерная проверка на синтетических товарах: запись, защита от повторного нажатия, оценка, замена исключённого товара, восстановление после перезагрузки, удаление, ширина 390 px и прежнее подтверждение корзины. Реальная корзина во время тестов не создаётся.
