# Включение OAuth ВкусВилла

Вход и свежий черновик корзины проверены пользователем на телефоне. Сохранение входа добавлено отдельно и требует повторного входа после обновления. Публичный каталог через опубликованный Cloudflare Worker уже работает; прямой доступ из среды разработки получает Access Blocked. Для moe-pitanie-2 OAUTH_ENABLED=true, но вход остаётся закрыт до наличия всех Secrets и корректной конфигурации; для отдельного staging/старого production флаг false. Адреса OAuth подтверждены живыми metadata; включать только после регистрации клиента, настройки и проверки.

## Регистрация и настройки

1. В личном кабинете ВкусВилл установить точный адрес в Долгопрудном.
2. На https://vkusvill.ru/oauth/registration/ зарегистрировать персонального клиента. Для production Redirect URI: **https://moe-pitanie-api.statusdi.workers.dev/oauth/callback**. Для нового moe-pitanie-2: **https://moe-pitanie-2.statusdi.workers.dev/oauth/callback**. Для отдельного staging: **https://moe-pitanie-api-staging.statusdi.workers.dev/oauth/callback**. Поддержку нескольких callback одним клиентом нужно подтвердить при регистрации; если зарегистрирован только production, staging OAuth не включать.
3. В конфигурации уже установлены проверенные значения: VV_AUTHORIZATION_ENDPOINT=https://oauth.vkusvill.ru/oauth2/auth, VV_TOKEN_ENDPOINT=https://oauth.vkusvill.ru/oauth2/token, VV_SCOPE=catalog.search, VV_TOKEN_AUTH_METHOD=client_secret_post. Адреса и методы подтверждены [живыми metadata](https://oauth.vkusvill.ru/.well-known/oauth-authorization-server); scope и отправка client secret в body — [официальным CLI](https://github.com/vkustech/vkusvill-cli/blob/e49df83b43429c32cb5c9c6bbd6154757f72bb1a/src/auth.js). При регистрации разрешить минимальный доступ к каталогу, без истории, персональных скидок и offline_access. Refresh пока не реализован.
4. После развёртывания кода через Wrangler открыть Cloudflare Dashboard → Workers & Pages → выбранный Worker → Settings → Variables and Secrets. Добавить Secrets: **VV_CLIENT_ID**, **VV_CLIENT_SECRET**, **TOKEN_ENCRYPTION_KEY**. Значения клиента — из письма ВкусВилла. Ключ — 32 случайных байта в base64url. С телефона откройте [страницу создания ключа](https://dinaray.github.io/Moe_pitanie/setup-key.html): ключ генерируется Web Crypto только в памяти вашего устройства, не отправляется по сети и не сохраняется в storage. Нажмите «Создать и скопировать ключ» и вставьте его только в Cloudflare Secret. Если ключ уже сохранён, не заменять его без необходимости.

   Генерация на доверенном компьютере:

   ```sh
   node -e "console.log(require('node:crypto').randomBytes(32).toString('base64url'))"
   ```

   Не присылать ключи или письмо в чат, не сохранять в git. В коде и тестах нет настоящих секретов. При смене ключа существующие сессии становятся нечитаемыми: нужен новый вход.
5. Обычные переменные Worker: подтверждённые VV_AUTHORIZATION_ENDPOINT, VV_TOKEN_ENDPOINT, VV_SCOPE, VV_TOKEN_AUTH_METHOD. Проверить **VV_REDIRECT_URI** (точное совпадение с регистрацией), **APP_RETURN_URL=https://dinaray.github.io/Moe_pitanie/connect.html**, **ALLOWED_ORIGIN=https://dinaray.github.io**. **APP_ENV=staging** на тестовом Worker, **production** на основном. После проверки всех значений установить OAUTH_ENABLED=true. CATALOG_ENABLED включается отдельно.
6. В allowlist разрешены HTTPS OAuth endpoints только на подтверждённом oauth.vkusvill.ru, без credentials/query/fragment. Если официальный issuer сообщает другой домен, его сначала нужно проверить и явно добавить в конфигурационный валидатор. Нельзя отключать проверку доменов или использовать адреса из случайных примеров.
7. Развёртывать весь worker/, а не один JS файл: нужны binding AUTH_STORE, SQLite Durable Objects migration и CATALOG_LIMITER из wrangler.jsonc. Не удалять историю migrations после первого deploy. Имя Worker по умолчанию moe-pitanie-2. Для отдельного staging использовать wrangler.staging.jsonc. Для production использовать отдельную wrangler.production.jsonc, как описано в INTEGRATION.md.
8. После объединения PR и обновления GitHub Pages открыть **connect.html**, выбрать основной или тестовый сервер. Страница проверит готовность. При Hello World!, недоступности Worker или незаполненном OAuth кнопка входа недоступна. Основное примерное меню продолжает работать. После каждого deploy перепроверять /api/status: значения, явно перечисленные в wrangler.jsonc (включая флаги false), имеют приоритет над Dashboard. keep_vars сохраняет дополнительные переменные, но не отменяет этот приоритет. Включать флаги через Dashboard после deploy либо изменять их явно в конфигурации перед проверенным deploy.

## Как устроен вход

- Верхнеуровневый переход /oauth/start создаёт PKCE S256, случайный state и HttpOnly Secure SameSite=Lax cookie привязки браузера. State/verifier зашифрованы на сервере и действуют 10 минут.
- Callback проверяет cookie и state, атомарно погашает state, затем обменивает code на токен сервер-сервер. Повторное использование отклоняется. Redirect и адрес обмена берутся только из проверенной конфигурации. Сетевые redirects запрещены.
- Access token хранится в Durable Object зашифрованным AES-GCM. Ключ хранится в Worker Secret; каждая запись криптографически привязана к случайному идентификатору сессии. Имена объектов используют SHA-256 идентификаторов. Refresh token не сохраняется.
- Браузер получает через fragment только случайный идентификатор сессии приложения, **не токен ВкусВилла**. JS сразу очищает fragment и держит идентификатор API в памяти вкладки. В localStorage сохраняются только предпочтение «Сохранять вход», имя выбранного сервера и время истечения — без идентификатора сессии, access token, refresh token или ключей. Внешних скриптов нет, действуют CSP и Referrer-Policy.
- API использует идентификатор приложения в Authorization. При выбранном «Сохранять вход» callback дополнительно устанавливает host-only cookie __Host-moe_session (HttpOnly, Secure, SameSite=Lax). После повторного открытия приложение делает переход верхнего уровня на /oauth/restore; cookie отправляется как first-party, сервер проверяет зашифрованную запись и возвращает сессию в fragment фиксированного APP_RETURN_URL. Сторонние cookies не требуются, новый обмен у ВкусВилла не выполняется. Без сохранения сессия живёт до часа; с сохранением — до суток. Оба срока ограничены реальным expires_in токена. При отсутствии/истечении cookie восстановление закрывается с auth=expired без цикла перенаправлений. Logout удаляет серверную запись и локальный несекретный маркер; оставшаяся cookie больше не даёт доступ и удаляется при обращении к restore. Полный отзыв grant выполняется отдельно у ВкусВилла.
- Сессии разных пользователей изолированы. Нет общих пользовательских токенов в глобальной переменной Worker. Внешние Cookie/Authorization не проксируются в MCP: OAuth-токен выбирается только после серверной проверки сессии.

## Проверка перед production

Нужны живые проверки на телефоне: вход, отказ на consent, повторный/неверный state, истечение сессии, logout и изоляция пользователей. Подтвердить текущий scope и каталог адреса с помощью tools/list/search. Не записывать в логи заголовки, тело token exchange, callback query, идентификаторы сессий и персональные ответы. Автоматические тесты используют только фиктивные значения.

Вход сам по себе не подтверждает наличие: у каждого товара оно известно только при авторизованном ответе и явном числовом available_quantity. Адаптер товаров, расчёты, двухдневное меню и подтверждение корзины реализованы по схеме официального CLI, но ещё требуют живой проверки из Cloudflare. Для moe-pitanie-2 CART_ENABLED=true; создание только ссылки разрешено после явного подтверждения свежего черновика. В отдельных staging/production-конфигурациях флаг false. Старая сумма и отметка подтверждения не сохраняются при обновлении страницы. /api/cart/draft выполняет только чтение и расчёт, требует действующую сессию.

/api/status сообщает только наличие Client ID/Secret и валидность ключа (oauthSetup), без значений. Эти флаги нужны для сопровождения настройки.
